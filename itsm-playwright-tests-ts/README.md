## Setup

```bash
npm install
npx playwright install   # downloads browser binaries
```

## Running

```bash
npm test                 # everything (runs the login setup project first)
npm run test:admin       # admin dashboard tests
npm run test:employee    # employee dashboard tests
npm run test:it-staff    # IT staff dashboard tests
npm run test:ui          # interactive UI mode — best for fixing selectors
```

`fixtures/auth.setup.ts` logs in once per role and saves the session to
`auth/*.json`; the `admin`, `employee`, and `it-staff` Playwright projects
reuse that session via `storageState`, so most tests start already logged in.
`tests/admin/login.spec.ts` is the exception — it runs unauthenticated,
since it's testing the login form itself.

## What's real vs. what needs your input

- **`tests/admin/login.spec.ts`** (ITSM-01 to ITSM-04, 13 tests) is fully
  wired up with the actual credentials from the "All the possible passwords"
  sheet (`config/env.ts`). This one should run close to as-is once the
  `getByLabel`/`getByRole` selectors in `pages/common/LoginPage.ts` are
  confirmed against the real login form.
- **Every other spec** (796 tests) was generated by parsing each row's
  *Steps* and *Expected Result* text into `test.step()` blocks. Where the
  step is an unambiguous action ("Click X", "Open <url>"), it's wired to a
  real Playwright call via the semantic helpers in
  `pages/common/BasePage.ts` (`base.click('X')` → matches by visible
  role/text). Where the step is ambiguous ("Enter valid title", "Inspect
  requester information"), it's left as a `// TODO:` comment with the
  original wording, so nothing is silently guessed.
- Search each file for `// TODO` to find exactly what's left to wire up —
  mostly form-field fill-ins and a handful of custom assertions
  (e.g. "SLA severity persists after refresh").

## Recommended next steps

   login field labels and error state, since every other role's login
   depends on the same `LoginPage`.
2. Once login works, run one module at a time (e.g. `alert-management.spec.ts`)
   in UI mode and fix `// TODO`s as you go — the test titles carry the
   original Test ID (`[AM-012] Create alert with required fields`) so you
   can cross-reference the spreadsheet.
3. Move your highest-value tests into `tests/smoke/` once they're passing,
   for a fast pre-release check.
